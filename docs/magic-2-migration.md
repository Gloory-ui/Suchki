# Магия 2.0: карта миграции к 12 школам и 200+ заклинаниям

Этот документ фиксирует фактическое состояние ветки `origin/claude/exciting-thompson-aan34c`. Он отделяет уже
написанный контент от целевой комплектации, чтобы промежуточный код не выдавался за законченные 200+ заклинаний.

## Что действительно находится в WIP-ветке

поэтому двенадцатая школа пока существует только как категория. У всех 105 записей есть RU/EN-название,
описание и иконка; рецепты отсутствуют только у высоких рангов, которые по правилам генератора должны находиться
как добыча. Ключи RU и EN совпадают.

Надпись «200+» не подтверждается состоянием удалённой ветки: до 200 не хватает 95 заклинаний, а до симметричной

репозитория и его нужно предоставить отдельно.

## Целевая комплектация 204

Для каждой школы резервируется 17 мест: ранги `3 / 3 / 3 / 2 / 2 / 2 / 2`. Это даёт достаточно ранней магии,
не превращая высшие ранги в один-единственный ультимейт.

`tools/validate_magic_catalog.py` проверяет текущую рабочую копию. Обычный режим контролирует целостность и
показывает расстояние до цели; `--strict-target` становится релизным гейтом для 12 школ и 204 заклинаний:

```bash
python tools/validate_magic_catalog.py
python tools/validate_magic_catalog.py --strict-target
```

## Почему ветку нельзя сливать целиком

Каждая школа сейчас является монолитом от 1013 до 1643 строк (`SummonSpells` — 1485, `EarthSpells` — 1643).
Одновременный перенос меняет школы, ранги, сетевой протокол, сохранения, визуальные эффекты, генераторы ресурсов,
местность и тестовую систему. Ошибка в одной подсистеме блокирует проверку всех остальных.

Безопасная единица миграции — одна школа, разделённая на:

1. `catalog` — декларативные параметры, текст, фраза, ингредиенты, профиль визуала;
2. `actions` — небольшие обработчики механик, сгруппированные по типу, а не один класс на 1500 строк;
3. `terrain` — общий бюджетируемый API воронок, разломов, тоннелей и следов;
4. `tests` — минимум один позитивный, граничный и защитный сценарий на заклинание;
5. `resources` — иконка, книга, RU/EN, звук и профиль круга, проверяемые генератором.

## Порядок переноса

### PR 1 — контракты ядра

- 12 значений `School`, ранги 1…7 и совместимая миграция старых семи школ;
- версионированные сохранения известных заклинаний;
- ограниченный сетевой codec для id;
- data-driven каталог и валидатор ресурсов;
- общий `SpellKit`, `Targeting`, бюджетируемые `Terrain`/`Trail` и FX-протокол;
- преобразование старых id: `destruction → fire`, `restoration → life`, `alteration → earth/space`,
  `illusion → mind`, `conjuration → summon`; неоднозначные изученные заклинания мигрируются по собственному id.

Нельзя просто заменить enum: сохранённый выбор школы и содержимое книг должны пережить обновление мира.

### PR 2–4 — девять наиболее полных школ

Переносить тремя наборами, но ревью и тестовый отчёт вести отдельно по каждой школе:

- Огонь, Вода, Жизнь — контент из диапазона коммитов `d8c77d5…3923de2`;
- Тьма, Пространство, Земля — `1e6e05e…5a7f8b2`;
- Ветер, Молния, Свет — `b6d70d2`.

Это не рекомендации для `cherry-pick`: коммиты зависят от полной замены ядра. Источники нужно переносить по
заклинаниям, оставляя эффект, тест и ресурсы в одном PR.

### PR 5 — Разум

Перенести код и существующий подробный `MindSpellTests`, затем отдельно проверить AI-состояния: выгрузку чанка,
смерть/перезаход владельца, конфликт целей, боссов и нескольких магов. До этого школа остаётся experimental.

### PR 6 — Призыв

Не переносить как готовую школу, пока пустой `SummonSpellTests` не покрывает срок жизни, лимиты существ,
владельца, смену измерения, смерть, выгрузку чанка, инвентарь спектрального оружия и очистку attachments.

### PR 7 — Слияние

Спроектировать 17 заклинаний-комбинаций. Каждое хранит 2–3 исходные школы и требует хотя бы одно изученное
заклинание каждой составляющей. Слияние не должно дублировать обычный урон: его роль — комбинированная геометрия,
изменение местности, состояние поля боя и командные связки.

### PR 8+ — заполнение до 204

Добавлять недостающие 99 заклинаний вертикальными срезами по 6–12 штук. PR считается законченным только когда
одновременно присутствуют механика, визуал, звук, локализации, книга/loot-правило и тесты. После достижения цели
CI переключается на `python tools/validate_magic_catalog.py --strict-target`.

## Обязательные ворота качества школы

- все id уникальны и переживают миграцию;
- RU/EN имеют одинаковые ключи, числа в описании соответствуют коду;
- ранги 1–4 имеют корректные рецепты, ранги 5–7 — явное loot-правило;
- эффекты местности уважают лимит блоков, `mobGriefing`, block entities и неразрушимые/защищённые блоки;
- ни один эффект не форсирует загрузку удалённых чанков;
- мультикаст умножает стоимость и визуал, но не обходит лимиты сущностей/местности;
- тесты охватывают отсутствие цели, союзника, PvP, край радиуса, смену измерения и перезаход;
- выделенный сервер не загружает клиентские классы, а клиент с минимальной детализацией сохраняет читаемость.
